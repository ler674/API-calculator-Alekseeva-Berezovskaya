# Анализ работы инструментов безопасности

## 1. Использованные инструменты безопасности

При создании пайплайна были внедрены 7 инструментов безопасности с открытым исходным кодом.

| Инструмент    | Категория          | Что проверяет                                                                                      |
|:--------------|:-------------------|:---------------------------------------------------------------------------------------------------|
| **Semgrep**   | SAST               | Ищет небезопасные паттерны и уязвимости в исходном коде.                                           |
| **Bandit**    | SAST               | Специализированный сканер для Python.                                                              |
| **pip-audit** | SCA                | Анализирует зависимости из `requirements.txt` на наличие известных CVE-уязвимостей.                |
| **Checkov**   | IaC                | Анализирует инфраструктуру как код (`Dockerfile` и YAML-файлы GitHub Actions).                     |
| **Gitleaks**  | Secrets            | Сканирует код и историю коммитов на наличие случайно оставленных паролей, токенов и API-ключей.    |
| **Hadolint**  | IaC                | Проверяет `Dockerfile` на соответствие лучшим практикам и наличие потенциальных ошибок.            |
| **Trivy**     | Container Security | Сканирует готовый Docker-образ (системные пакеты ОС Debian и Python-библиотеки внутри контейнера). |

## 2. Анализ отчетов инструментов безопасности

### Semgrep

Работа завершилась с ошибкой: `ValueError: invalid rule severity value: MEDIUM`.

Сбой произошел не в коде калькулятора, а в конфигурации Semgrep. Оказалось, что используемая версия GitHub Action (`semgrep/semgrep-action@v1`) устарела и не может корректно обработать уровни критичности правил. Из-за этого анализ кода Semgrep фактически не был произведен.

### pip-audit

При анализе найдено 16 уязвимостей в 2 пакетах.

В частности:

- `pytest 8.3.4` - Обнаружена уязвимость `PYSEC-2026-1845`, связанная с использованием небезопасных временных директорий, что позволяет локальным пользователям вызвать отказ в обслуживании или повысить привилегии.
- `starlette 0.41.3` - Множественные уязвимости (`PYSEC-2026-1941`, `PYSEC-2026-1942`, `PYSEC-2026-161` и другие), включая связанные с DoS через HTTP-заголовок `Range`, обход авторизации через подмену заголовка `Host` и другие.

### Checkov

В результате проверки `Dockerfile` пройден без ошибок (48 проверок), а файлах пайплайна найдена 1 ошибка.

Ошибка в пайплайне: `CKV2_GHA_1: "Ensure top-level permissions are not set to write-all"`. То есть выданы избыточные права, что нарушает принцип наименьших привилегий и создает риск компрометации всего репозитория в случае атаки на пайплайн.

## 3. Cлабые места

1. Уязвимости в зависимостях, из-за которых высока вероятность проведения успешной DoS-атаки на API-калькулятор, а также возможно несанкционированное повышение привелегий.
2. В контейнере используется базовый образ на основе `Debian 13.7`, который содержит очень много уязвимостей, которые потенциально увеличивают поверхность атаки.
3. Избыточные права в пайплайне нарушают принцип наименьших привелегий, что увеличивает риски.
4. Ошибочная конфигурация Semgrep, не дала выполнить анализ кода с помощью этого инструмента.

## 4. Возможные варианты повышения безопасности

1. Обновить зависимости в файле `requirements.txt`: обновить `fastapi` (который и подтягивает `starlette`) до актуальной версии, обновить `pytest` до актуальной версии, с исправленной уязвимостью.
2. Перейти с `python:3.12-slim` (Debian) на `python:3.12-alpine`. Alpine-образы значительно меньше по размеру и содержат меньше системных пакетов (а значит, и меньше CVE).
3. Настроить регулярную пересборку образа, чтобы подтягивались свежие патчи безопасности `Debian`.
4. В пайплайне исправить избыточные права, оставить только необходимые.
5. Исправить конфигурацию Semgrep, чтобы анализ кода проводился.
